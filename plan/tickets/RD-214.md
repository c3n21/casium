# RD-214 Introduce The Tailwind + shadcn Design System

## Goal
Give the app one styling mechanism, so the next four tickets build on primitives instead of inline style objects.

## Implementation
Add Tailwind v4 and shadcn to `apps/web`. **Port the existing palette rather than accepting shadcn defaults** — `globals.css:4-18` defines `--ink`, `--paper`, `--paper-2`, `--panel`, `--line`, `--blue-deep`, `--mint`, `--amber`, and a 22px radius, and that warm paper aesthetic is the app's visual identity. Move those into Tailwind's `@theme` and let shadcn's generated components read them, or the overhaul will make the app look like every other shadcn demo. Generate only what the epic needs: Button, Card, Input, Textarea, Select, Badge, Alert, Dialog, ScrollArea, Skeleton, Avatar. Then delete the inline styles: the two local `inputStyle`/`buttonStyle` pairs (`MandateForm.tsx:374-392`, `PacketBuilder.tsx:291-292`) and the inline `style={{…}}` props throughout `apps/web/src/components/` and `apps/web/app/`. Keep `data-ui="button"` and `data-ui="secondary"` working, or as a deliberate removal with every call site updated — several E2E specs and `globals.css:79-81` depend on them. Do **not** change component behavior in this ticket; a diff that is purely presentational is one that can be reviewed.

## Done when
- [ ] `pnpm --filter @casium/web build` and `typecheck` both pass.
- [ ] Zero `style={{` occurrences remain under `apps/web/src/components/` and `apps/web/app/`.
- [ ] The rendered palette is visibly the current one, not shadcn's default neutral.
- [ ] All existing E2E selectors still resolve.

## Verify
- **Tests.** No new unit tests. `pnpm test:e2e` (stubbed tier) must pass unchanged — this ticket changes appearance, not structure.
- **Evidence to capture.** Before/after screenshots of `/`, `/renter`, `/provider`, `/landlord`, plus a passing stubbed E2E run.

## Notes
- **Failure fallback.** If shadcn's Radix dependency footprint proves disruptive, fall back to Tailwind plus hand-written primitives; the palette port and inline-style removal are the load-bearing half of this ticket.
- **Parallel safety.** Touches nearly every file in `apps/web`. **Do not run concurrently with RD-216 … RD-219.** Land it first, or accept the merge cost.
- **Demo impact.** High and immediate — this is the half of the overhaul a viewer sees first.
