# RD-217 Add The Review Card And The Commit Flow

## Goal
Turn a reviewed, edited draft into an on-chain mandate and one encrypted packet per confirmed listing, in a single deliberate action.

## Implementation
- The assistant's turn renders three confirmable artifacts: a **mandate card** (every field editable, including `expiresAtMs` and `permittedActions`, which the old form never exposed at all), a **wants card** (the v2 packet fields plus attachment thumbnails), and **listing match cards** built from `listingMatches`, each showing its `reasons` so a match is explained rather than asserted.
- The renter edits freely; the mandate card is the review step the *Rules* section requires, and it must show what the model filled versus what the renter changed. One primary action then runs, strictly ordered: (1) wallet-sign `create_mandate` via the existing `signAndExecuteWithExplicitGas` path, reusing `parseCreatedMandate` from `MandateForm.tsx:333-372` — lift it into `apps/web/src/lib/mandate.ts` rather than duplicating it; (2) for each confirmed listing, Seal-encrypt a wants packet bound to `{ mandateId, listingObjectId }` and upload to Walrus; (3) `POST /packets` for each.
- Order matters — the mandate must exist before packets reference it, and a failed signature must upload nothing. Render per-listing progress (`pending → encrypting → uploading → registered`) and make a partial failure resumable: if three of five uploads succeed, retry the two rather than redoing all five.
- Reuse the encryption and upload logic in `PacketBuilder.tsx:100-204` — extract it into `apps/web/src/lib/packetUpload.ts` and let the old component and the new flow share it, so the Seal and mock branches do not fork.
- Repeat the leak warning on this card; it is the last screen before bytes become permanent.

## Done when
- [ ] Editing any mandate field before signing changes what is submitted on chain.
- [ ] A rejected wallet signature uploads nothing.
- [ ] With three listings confirmed, three packets are registered, each with a distinct `packetHash` bound to its own `listingObjectId`.
- [ ] A failure on the second upload leaves the first registered and offers a retry that does not re-sign the mandate.

## Verify
- **Tests.** Unit tests for the commit reducer: ordering, partial-failure state, retry idempotency. Wallet-path coverage lands in RD-220's live tier.
- **Evidence to capture.** A live testnet run: mandate transaction digest, the created object IDs, and one `POST /packets` response per listing.

## Notes
- **Failure fallback.** If per-listing resumability proves expensive, ship all-or-nothing with a clear error — but say so in the ticket rather than leaving a half-uploaded state undocumented.
- **Parallel safety.** Shares `renter/page.tsx` with RD-216 and `PacketBuilder.tsx` with nothing else in this epic.
- **Integration.** Sui (the mandate transaction), Seal and Walrus (per-listing packets).
- **Demo impact.** Highest alongside RD-216 — this is where "the model proposes, the human signs, Sui enforces" becomes visible in one screen.
