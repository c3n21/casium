# RD-117 Withdraw Application End-To-End

## Goal
Expose the revocability story that already exists in Move but has no path above it.

## Implementation
`withdraw_application` is implemented and tested in `packages/move/sources/rental.move:277` but has no PTB builder consumer, no API route, and no UI. Add a renter-side withdraw button (requires `OwnerCap`) using the existing `buildWithdrawApplicationTx`, call RD-110's withdraw endpoint with the digest, and show the receipt flipping to withdrawn on the landlord and provider views.

## Done when
- [ ] Renter withdraws; receipt `status` becomes `2` on chain; provider marks the row withdrawn only after verifying the transaction; landlord view reflects it.

## Verify
- **Tests.** Move tests already cover the abort paths; add API verification tests and a component test.
- **Evidence to capture.** Live testnet withdrawal with digest and before/after receipt state.
- **Browser.** Required — the renter signs with a wallet. Read the wallet signing pitfalls in `docs/browser-testing.md` before starting; explicit gas is not optional.

## Notes
- **Failure fallback.** CLI-only withdrawal, documented.
- **Parallel safety.** Depends on RD-110 and RD-114 both landing.
- **Integration.** Sui.
- **Demo impact.** Completes "inspectable *and* revocable" — currently only revoke-mandate is reachable.
