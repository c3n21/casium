# RD-180 Make AgentKit Mode Configuration Self-Consistent

> Deliberately deferred by the user until the active epics are done — but this must be
> fixed before any demo that claims live World verification. Do not fix it inside an
> unrelated ticket.

## Goal
Stop the shipped `.env.example` from configuring a mode it cannot satisfy, and make the
resulting failure name its own cause.

## Context
- Copy `.env.example` to `.env` verbatim, upload a packet, click *Start run*, and the run
  fails with `401 AGENTKIT_UNVERIFIED` while `/agent` shows `agentkit: mock`.
- `AGENTKIT_MODE=real` selects the real verifier, which requires an `agentkit` header
  (`packages/agentkit/src/server.ts:118`).
- `AGENT_EVM_PRIVATE_KEY` ships commented out, so `createAgentkitSigner()` returns `null`
  (`apps/agent/src/agentkitSigner.ts:42`) and the agent cannot mint that header.
- `AGENTKIT_DEMO_*` is set, so the agent falls through to mock `x-demo-*` headers
  (`apps/agent/src/providerClient.ts:51-58`) — the exact set the real verifier ignores.
- The agent does warn at startup (`apps/agent/src/server.ts:57`), but it scrolls past in
  `.demo-logs/agent.log`. Tests pass because nothing exercises this pairing.

## Steps
1. Make `.env.example` self-consistent. Either default `AGENTKIT_MODE=mock` to match the
   credentials it actually ships, or keep `real` and make the missing
   `AGENT_EVM_PRIVATE_KEY` a **startup failure** rather than a silent downgrade. The second
   is more honest; the first is friendlier to a first run. Do not ship a mode the file
   cannot satisfy.
2. Make the mismatch self-diagnosing at the point of failure, not only at startup — the
   401 response body and the agent's error should both name the two disagreeing modes.
3. Document that registering an agent EVM key in AgentBook is a user action
   (`pnpm dlx @worldcoin/agentkit-cli register …`), where the operator actually hits the wall.
4. Add a test that pairs a `real`-mode provider with a mock-header agent and asserts the
   error names both modes. Its absence is why this survived.

## Constraints
- Never let a missing credential silently downgrade a mode anywhere in this repo.
- Do not claim live World verification on the demo path until this is closed.

## Done when
- [ ] `cp .env.example .env` followed by `pnpm demo:up` produces a working run, or fails at
      startup with a message naming the missing variable.
- [ ] A mode mismatch surfaces in the 401 body, not only in a startup log line.
- [ ] A test covers the mismatched pairing.

## Verify
- **Tests.** New provider/agent test for the mismatched mode pairing.
- **Evidence to capture.** A clean-clone run from `.env.example` through to a successful
  *Start run*, or the startup failure it now produces instead.
