# RD-212 Create The LLM Adapter Package With A Deterministic Mock

## Goal
Give the app one interface for turning a conversation into a mandate draft, a wants packet draft, and a listing shortlist — with a default implementation that needs no model.

## Implementation
- `packages/llm/` already exists as an untracked stub with `tsconfig.json` and `vitest.config.ts` and no `package.json` or `src/` — fill it rather than creating a new package. Follow the structure of `packages/walrus`: an `adapter.ts` declaring the interface, one file per implementation, and an `index.ts` factory that resolves mode from env.
- The interface is one call: `extractIntent({ messages, attachments, listings }) => Promise<ExtractionResult>`, where `ExtractionResult` is `{ mandate: MandateDraft, packet: WantsPacketDraft, listingMatches: ListingMatch[], rationale: string }`.
- Validate the result with Zod derived from `CreateMandateSchema` (minus `agentSuiAddress`/`agentEvmAddress`, which come from `GET /identity` and are never model output) and `WantsPacketSchema` from RD-211 — an adapter that returns an unparseable draft must fail loudly at the boundary, not produce a half-filled form. `createMockLlmAdapter()` is deterministic keyword extraction: municipality names from the same table as the app (import it, do not re-type it — see the duplication noted in *Why This Epic Exists*), a EUR amount by regex, bedroom counts from number-words and digits, and boolean flags for pets/furnished/parking/outdoor. `ListingMatch` carries `{ listingId, score, reasons: string[] }` so the UI can explain a match rather than asserting one.

## Done when
- [ ] `extractIntent` on "two bedrooms in Oeiras or Cascais, under €1800, I have a cat" yields `allowedMunicipalities: [2, 3]`, `minBedrooms: 2`, `maxMonthlyRentEur: 1800`, and `pets: true`.
- [ ] The same input twice yields byte-identical output.
- [ ] A malformed adapter response fails Zod parsing rather than reaching the caller.

## Verify
- **Tests.** Unit tests over a table of ~12 phrasings including negations ("no pets"), ranges ("1500 to 1800"), and unmatched input (which must produce a draft with fields absent, not fabricated defaults).
- **Evidence to capture.** `pnpm --filter @casium/llm test` output.

## Notes
- **Failure fallback.** None; the mock *is* the fallback for RD-213.
- **Parallel safety.** Owns `packages/llm/` entirely.
- **Integration.** None directly — this is new local infrastructure.
- **Demo impact.** High. The mock is the default demo path, so its extraction quality is what a viewer actually sees.
