# RD-211 Replace The Packet Document With An Apartment-Wants Packet

## Goal
Make the encrypted document describe an apartment instead of a person, so the no-identity claim is structural rather than aspirational.

## Implementation
Rewrite `packages/shared/src/packet.ts` to the *Packet v2* shape in `plan/epics/O.md`. This is a replacement, not an edit: `renterName`, `nationalId`, `payslipMonthlyNetEur`, `employerName`, `employmentType`, `referenceName`, `referenceRelation`, `proofOfFundsEur` are all deleted, and `coverLetter` becomes the optional `note`. Keep the v1 schema exported as `PacketDocumentSchemaV1` — RD-218 needs it to render archived blobs, and deleting it would silently break every packet already on Walrus. Export a discriminated union `AnyPacketSchema` keyed on `version` so a reader can parse either without guessing. Replace `makeSyntheticPacket` with `makeWantsPacket(overrides?)` and keep `SYNTHETIC_PACKET_DEFAULTS`'s role as `WANTS_PACKET_DEFAULTS` — several tests and the E2E fixtures build packets from defaults. Grep before finishing: `renterName` alone appears in `apps/web/src/lib/packet.test.ts`, `PacketViewer.tsx`, `PacketBuilder.tsx`, `apps/e2e/src/restoreNextEnv.ts`, and `spec/development-spec.md`.

## Done when
- [ ] `WantsPacketSchema` rejects any object carrying a `renterName`, `nationalId`, or `payslipMonthlyNetEur` key.
- [ ] A v1 fixture still parses through `PacketDocumentSchemaV1`.
- [ ] `AnyPacketSchema` routes both versions correctly on `version`.
- [ ] No PII field name survives anywhere in `packages/shared`.

## Verify
- **Tests.** Extend `packet.test.ts`: v2 round-trip; v1 fixture still parses; `containsPersonalData: true` is rejected; a non-image attachment MIME is rejected; a seventh attachment is rejected.
- **Evidence to capture.** `pnpm --filter @casium/shared test` output, plus a grep showing zero PII field names in `packages/shared/src`.
