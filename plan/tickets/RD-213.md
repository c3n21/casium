# RD-213 Add The llama-cpp Adapter Behind LLM_MODE

## Goal
Make the extraction real when a model is available, without making the demo depend on one being present.

## Implementation
`createLlamaCppAdapter()` using `node-llama-cpp` with a small instruct GGUF. Constrain generation with a **grammar** built from the same Zod schemas rather than prompting for JSON and hoping — free-form JSON from a small model is the failure mode this ticket exists to avoid. Resolve mode in the `index.ts` factory: `LLM_MODE` of `mock | llama-cpp`, defaulting to `mock`, mirroring `getWalrusMode()`. The model path comes from `LLM_MODEL_PATH`; if the mode is `llama-cpp` and the file is absent, **fail at startup with a message naming the variable** rather than silently falling back to mock — the silent-downgrade pattern is exactly what produced RD-180, and this epic should not add a second instance of it. Add `pnpm --filter @casium/llm check:env` alongside the existing `@casium/walrus` and `@casium/agent` env checks. Transcription and vision stay mocked here; they get their own interface methods (`transcribe`, `describeImage`) so a later ticket can implement them without touching callers.

## Done when
- [ ] With `LLM_MODE=mock` (default) nothing is downloaded and no native module loads.
- [ ] With `LLM_MODE=llama-cpp` and a valid `LLM_MODEL_PATH`, extraction returns schema-valid drafts.
- [ ] With `LLM_MODE=llama-cpp` and no model file, the process exits with an error naming `LLM_MODEL_PATH`.

## Verify
- **Tests.** Adapter-selection tests over env permutations. The llama-cpp path itself is integration-tested manually and marked skipped in CI — do not add a test that downloads a model.
- **Evidence to capture.** `check:env` output in both modes, plus one manual extraction transcript recorded in the ticket.

## Notes
- **Failure fallback.** Ship with `LLM_MODE=mock`. The epic is fully demoable without this ticket.
- **Parallel safety.** Owns `packages/llm/src/llamaCpp.ts`. Coordinate with RD-212 on `index.ts`.
- **Integration.** None directly.
- **Demo impact.** Optional. Real extraction is a better story; mock extraction is a working one.
