# RD-118 Correlation IDs And Structured Logging

## Goal
Implement spec §16, which is currently specified and entirely absent from the code.

## Implementation
`grep -rn "correlationId" apps packages` returns nothing today. Add middleware that accepts or mints an `x-correlation-id`, propagate it from the agent through every provider request, and emit structured JSON logs carrying the field set in spec §16 (`applicationId`, `mandateId`, `receiptId`, `txDigest`, `agentEvmAddress`, `agentSuiAddress`, `humanIdHash`, `walrusBlobId`). `humanIdHash` may be logged; the raw World human ID must never be. Never log key material or ciphertext.

## Done when
- [ ] One agent run produces a single correlation ID traceable across agent logs, provider logs, and the stored application row.
- [ ] A log-scrubbing test proves no secret or raw human ID is emitted.

## Verify
- **Tests.** Middleware unit tests; a redaction test asserting forbidden fields never appear.
- **Evidence to capture.** Paste one correlated trace across both processes.

## Notes
- **Failure fallback.** Correlation ID propagation alone, without full structured logging.
- **Parallel safety.** Additive middleware; safe alongside most tickets once RD-109 lands.
- **Integration.** None directly.
- **Demo impact.** Low on stage, high during the build.
