# RD-216 Rebuild /renter As A Conversation

## Goal
Let the renter describe the home they want in their own words, with images and voice, instead of filling in two forms.

## Implementation
Replace the form-driven body of `apps/web/app/renter/page.tsx` (541 lines) with a conversation: a message thread, and a composer with a text field, a mic button, and an image attach button. Attachments render as thumbnail chips with a remove control. The **leak warning sits inline in the composer**, adjacent to the attach button, permanently — not in a dismissable modal, which is read once and then never again: *"Attach photos of what you're looking for. Don't attach your ID, payslips, or anything personal."* Ship a small fixture gallery (`apps/web/public/fixtures/`) of obviously-synthetic property photos so the demo has a consistent, safe attach path, and so a viewer is not required to open their own filesystem. Enforce image MIME types and a per-file cap of a few MB client-side; both are also enforced in RD-215. The mic button records and posts audio to `transcribe`, showing the `llmMode` badge next to the transcript so a mocked transcription is never mistaken for a real one. Keep the existing wallet-connect gate and the `demoSession` persistence — a renter who reloads mid-conversation should not lose it, so persist the thread alongside the existing mandate/listing keys.

## Done when
- [ ] A renter can hold a multi-turn conversation, attach a fixture image and a local image, and record audio, without the page reloading.
- [ ] The leak warning is visible whenever the attach control is.
- [ ] The LLM mode badge matches the resolved server mode.
- [ ] Reloading mid-conversation restores the thread.

## Verify
- **Tests.** Component tests for the composer's MIME and size rejection paths. E2E coverage lands in RD-220.
- **Evidence to capture.** Browser walkthrough per `docs/browser-testing.md`, capturing the composer, an attached fixture, and the mode badge.

## Notes
- **Failure fallback.** If the mic path proves unreliable across browsers, ship text and images and file the audio work separately — the epic does not depend on voice.
- **Parallel safety.** Owns `apps/web/app/renter/page.tsx` and `apps/web/src/components/chat/`. Conflicts with RD-217 — same owner should take both, RD-216 first.
- **Integration.** None directly.
- **Demo impact.** Highest in the epic. This is the screen the overhaul exists to produce.
