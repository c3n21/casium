# RD-218 Teach The Landlord Inbox To Read Wants Packets

## Goal
Give the landlord a decrypted view of what an anonymous applicant is looking for, and a way to act on it.

## Implementation
- `PacketViewer` (`apps/web/src/components/PacketViewer.tsx`, 523 lines) currently renders an identity dossier. Rewrite the presentation layer while leaving the Seal session, `seal_approve_packet` dry-run, and decrypt path untouched — that path is live-proven and this ticket must not disturb it.
- Parse decrypted bytes through `AnyPacketSchema` and branch on `version`: v1 renders as today (archived blobs must stay readable, per *Rules*); v2 renders a wants profile — the renter's description, an image gallery from `attachments`, and the structured preferences as labeled chips.
- Show each attachment's `source` so fixture and renter-supplied images are distinguishable. Alongside the decrypted content, surface what the landlord *does* know without an identity: the World uniqueness attestation (`humanIdHash` is already on the application record, `ApplicationInbox.tsx:17`) and the on-chain mandate limits.
- Frame it explicitly — *a verified unique human, whose agent is bounded on chain, whose name you do not need yet.* Add an **express interest** action: a provider-side record on the application, not an on-chain state change, since `ApplicationReceipt.status` has two states and adding a third means a package upgrade for a field no policy reads (unchanged from Epic L's scope decision).
- Identity exchange happens off-platform and stays out of scope.

## Done when
- [ ] A v2 packet decrypts and renders as a wants profile with its images.
- [ ] A v1 packet from archived evidence still decrypts and renders.
- [ ] The wrong wallet is still denied by `ESEAL_WRONG_SENDER` with the existing message.
- [ ] Expressing interest persists across a provider restart.

## Verify
- **Tests.** Provider tests for the interest endpoint. Component tests for the v1/v2 branch on fixture packets. Live decrypt coverage lands in RD-220.
- **Evidence to capture.** Browser walkthrough: landlord wallet decrypts a v2 packet created by RD-217, and a wrong wallet is refused.

## Notes
- **Failure fallback.** Ship the read-only wants view without the interest action; the decrypt story stands alone.
- **Parallel safety.** Owns `PacketViewer.tsx`. Touches `applications.ts`, which Epic L's RD-185 also owns — check that ticket's status first.
- **Integration.** Seal (primary), Sui, Walrus, World (the uniqueness attestation the view leans on).
- **Demo impact.** High. This is where the no-identity claim is either visible or merely asserted.
