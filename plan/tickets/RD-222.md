# RD-222 Add a path alias to the web vitest config

## Goal
Let unit tests import `apps/web` components, so component behaviour can be asserted directly
instead of by reading source text.

## Context
- `apps/web/vitest.config.ts` defines `environment` and `exclude` but **no `resolve.alias`**,
  so any module importing `@/...` fails to resolve under vitest.
- Every component imports through the alias — e.g. `MandateForm.tsx` pulls
  `@/components/ui/button`, so the module cannot be loaded in a test at all.
- RD-221 hit this: its `MandateForm.test.ts` additions assert the derivation contract against
  `@casium/shared` and `fs.readFileSync` the component's source to check it imports from
  shared, because importing `MANDATE_MUNICIPALITIES` was impossible. See
  `plan/evidence/RD-221.md` → *Weaker than the ticket asked for*.
- `apps/web/tsconfig.json` already maps `@/*`; the vitest config just does not mirror it.

## Steps
1. Add a `resolve.alias` to `apps/web/vitest.config.ts` mapping `@/` to `apps/web/src`,
   matching `tsconfig.json`. Prefer deriving it from one source over restating the path twice.
2. Rewrite the source-text assertions in `MandateForm.test.ts` to import
   `MANDATE_MUNICIPALITIES` from the component and assert on the real value.
3. Keep the existing behavioural tests in that file passing unchanged.

## Constraints
- Do not change `MandateForm.tsx` itself — this ticket is about the test harness.
- `happy-dom` is the configured environment; do not switch it.
- Do not add a browser-mode or Playwright-backed component runner. `@vitest/browser` is
  installed but unused, and adopting it is a separate decision.

## Done when
- [ ] A test file can `import { MANDATE_MUNICIPALITIES } from "./MandateForm"` and run.
- [ ] `MandateForm.test.ts` no longer reads component source as a string to assert on it.
- [ ] `pnpm --filter @casium/web test` passes.

## Verify
- **Tests.** The rewritten assertions must fail if code 6 is reintroduced as a mandate option —
  prove it by temporarily removing the filter and showing the test goes red.
- **Evidence to capture.** The failing-then-passing output of that check.
