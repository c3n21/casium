# RD-200 Reduce the development spec to invariants and pointers

## Goal
Cut `spec/development-spec.md` down to the things no code file asserts, so it becomes a
document that is true and small enough to actually be read.

## Context
- It is 1,023 lines, ~12.8k tokens. No agent working in a 32k window can hold it alongside
  a ticket and source files, so in practice it is skipped — which makes calling it "the
  implementation contract" false.
- Large parts are verbatim duplicates of code. §4.1 and §4.2 are copies of
  `packages/shared/src/constants.ts`; the spec's copy of `MUNICIPALITIES` has already
  drifted from the two copies in `apps/web` (see RD-221).
- The repo already tells readers to distrust it — the standing guidance is that when the
  spec conflicts with executable config, trust the code. A document you are told not to
  trust is not a contract.
- What is genuinely unique is the *must-be-true* and *must-be-proven* content: preconditions,
  test matrices, required denial proofs, required failure cases, and the fallback ladder.

## Steps
1. Keep, and move to `spec/invariants.md`: §1 product contract and non-goals, §6.4
   `submit_application` preconditions, §6.6 Move test matrix, §11.5 required denial proofs,
   §17.2 required demo failure cases, §18 security rules, §19 fallback levels.
2. Delete and replace with a one-line pointer to the code that owns it:
   §4.1, §4.2 → `packages/shared/src/constants.ts`;
   §4.3 → `packages/contracts-config`;
   §4.4 → `packages/shared/src/schemas.ts`;
   §6.2, §6.3 → `packages/move/sources/rental.move`;
   §7.2, §7.3, §7.5 → the route files, `drizzle/`, and `docs/provider-api.md`;
   §10.1 → `packages/shared/src/packet.ts`;
   §14 → `.env.example`; §15 → `README.md`.
3. Check each "keep" section against the code before moving it — some describe a target
   state that was never built, and those must be marked as unbuilt or dropped, not carried
   over as if they were true.
4. Update every reference to `spec/development-spec.md` — `AGENTS.md`, `plan/backlog.md`,
   `plan/START.md`, the `spec:` frontmatter convention, and `docs/`.

## Constraints
- Do not delete a section merely because it is long. Delete it because something executable
  owns the same fact, and say where.
- Coordinate with RD-220, which also rewrites the packet sections of this file. One of the
  two should land first; do not run them concurrently.

## Done when
- [ ] `spec/invariants.md` is under 3k tokens and every claim in it is either currently true
      or explicitly labelled as not yet built.
- [ ] No section duplicates a constant, schema, endpoint list, or env var that code defines.
- [ ] No dangling reference to `spec/development-spec.md` remains in the repo.

## Verify
- **Tests.** None — documentation.
- **Evidence to capture.** Before/after token counts, and a grep showing zero references to
  removed section numbers.
