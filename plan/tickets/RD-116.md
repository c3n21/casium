# RD-116 `/agent` Operator Route

## Goal
Build the operator view the spec requires (§12) and the app does not have.

## Implementation
New `apps/web/app/agent/page.tsx`: mandate summary and remaining allowance, the eligible/ineligible listing evaluation with per-rule reasons, AgentKit mode and verification status, a "Run agent" button hitting RD-113's `POST /runs`, staged progress, and the resulting tx digest, receipt ID, and provider verification result with explorer links. Ineligible listings must show *why* in mandate terms.

## Done when
- [ ] The full agent story — scope, evaluation, refusal, submission, receipt — is visible in the browser with no terminal.
- [ ] Next build keeps prerendering all routes.

## Verify
- **Tests.** Component tests for each run stage and for the refusal rendering.
- **Evidence to capture.** Screenshot a successful run and a refused ineligible listing.
- **Browser.** Required — capture both the success path and the refusal with its mandate-terms reason. See `docs/browser-testing.md`.

## Notes
- **Failure fallback.** Read-only panel plus CLI trigger.
- **Parallel safety.** New file, but shares `apps/web/app` layout with RD-114.
- **Integration.** World, Sui.
- **Demo impact.** Currently the most compelling part of the system is only observable as terminal output.
