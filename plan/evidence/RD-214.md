## Findings worth carrying forward

- **Preflight is deliberately NOT imported.** `globals.css` imports the theme and utilities layers
  only. The app relies on browser-default margins for bare `p`/`h2`/`ul` outside `.card`/`.hero`, and
  on `globals.css`'s own element-level rules for `button`/`input`/`select`/`textarea`/`table`.
  Consequence: **any Tailwind border needs an explicit `border-solid`** — a width-only border renders
  as nothing. Every primitive that draws a border sets it.
- **Utilities lose to unlayered rules.** Because Tailwind sits in `layer(utilities)`, an unlayered
  rule in `globals.css` beats a utility on the same property regardless of specificity. This silently
  turned the home role-card headings blue (bare `a` rule vs `text-inherit`) and killed `font-mono` on
  the agent mandate field (`button,input,select,textarea{font:inherit}`). Both needed Tailwind's `!`
  suffix, at `app/page.tsx:53` and `app/agent/page.tsx:403`. **Neither was caught by code review — only
  by diffing screenshots.** The two suffixes cannot be removed: both conflicting rules are live.
- **Dead CSS was almost nonexistent.** Auditing all 31 legacy selectors found only `.thesis` and
  `.field` unreferenced. The other 29 are in use, several composed dynamically
  (`` `badge ${mode}` ``, `` `alert ${status}` ``), so a reference scan alone would have pruned live
  rules. The plan to "delete dead rules at the end" turned out to be a 4-line change.
- **The screenshot harness must not write to `test-results/`** — Playwright wipes that directory at
  the start of every run. It must also wait on route-specific testids; without a wait it captures the
  pre-paint gradient and different routes produce byte-identical images.
